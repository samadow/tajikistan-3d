# Development Plan — Tajikistan 3D

The plan is built from [TECHNICAL_AUDIT.md](TECHNICAL_AUDIT.md) and [ARCHITECTURE.md](ARCHITECTURE.md). Each phase ends with commands that must pass. A phase is "done" only when they have actually been run.

**Always-required checks**

```powershell
cd backend;  .venv\Scripts\python manage.py test
cd frontend; npm run typecheck; npm run build
```

Phase 1 adds `npm test` (Vitest) and Phase 3 adds `npm run e2e` (Playwright).

## Phase 1: Backend foundation ✅
**Goal:** a CMS and API that cover the whole content model, with versioned and documented endpoints.

| Task | Files |
|---|---|
| Move code into `apps/core`, `apps/landmarks`, `apps/stories` (keeping the migration history) | `backend/apps/**`, `config/settings/base.py` |
| Single projection file `shared/projection.json`, read by `geo.py` | `shared/`, `apps/core/geo.py` |
| New models and fields: `is_featured`, `LandmarkModel` (LOD + licence), `HistoricalSource`, `Era.is_reconstruction`, hotspot image/history/camera, `Story` / `StoryStep`, `SitePage` | `apps/*/models.py`, migrations |
| Data migration: existing `model_file` values → `LandmarkModel` | migration |
| `/api/v1/` with map, list (paginated + search), featured, nearby, detail, eras, stories, categories | `apps/*/views.py`, `urls.py` |
| drf-spectacular schema and docs | `requirements.txt`, `config/urls.py` |
| Django cache with a content-version key, invalidated by signals | `apps/core/cache.py` |
| Fix D5 (`NUM_PROXIES`) and D6 (missing-translation fields); validate the GLB magic header | settings, `models.py` |
| Admin: featured toggle, sources, LandmarkModel inline with sizes, story editor | `admin.py` |
| **Verify seed coordinates against OpenStreetMap/Wikidata** and record the source per landmark. Add Ancient Penjikent, the Fann Mountains and Tajik National Park (as areas). | `seed_landmarks.py` |
| Tests: serializers, translation fallback, upload validation, projection fixtures, every endpoint, cache invalidation | `apps/*/tests/` |
| Frontend switches to `/api/v1/` | `src/api/*` |

**Done when:** all backend tests pass, `/api/v1/docs/` renders, and the frontend still passes the E2E flows.

## Phase 2: Geographical terrain
| Task | Notes |
|---|---|
| Rivers and lakes: Natural Earth 10m rivers and lakes, OSM water bodies for the major lakes | Rendered as water meshes or lines draped on the relief |
| Baked hillshade + water mask texture (WebP/KTX2) | Removes the "plastic" look |
| Regional high-res heightmaps (zoom 11) per landmark, generated by the tool | ADR-6 |
| Optional colour imagery | **Blocked on the licensing decision (R2)** |
| Projection tests using shared fixture points (Python ↔ TypeScript) | Vitest + Django test |

## Phase 3: 3D engine
- Terrain mesh built in a Web Worker; a better geometry budget for the low tier.
- Markers drawn with **InstancedMesh**.
- Director: save/restore the camera view, fly to a hotspot, intro from a globe (public-domain Blue Marble texture).
- Fix D2 (lazy-load three.js and GSAP; the 2D fallback should not download three.js) and D3 (error boundary on terrain loading).
- Playwright E2E suite inside the repo.

## Phase 4: Landmark experience
- Fix **D1** (hotspots inside the fitted model space), hotspot panel and camera focus.
- LOD model selection per quality tier.
- Time machine: sources, a "reconstruction" badge, before/after comparison.
- New pages: Discover (search and filters), History (timeline across sites), About.
- Split `DetailPanel.tsx` and `Placeholders.tsx`. Fix D4 (locale-aware formatting) and D7.

## Phase 5: Cinematic experience
- CMS-driven stories, story progress and navigation UI, reduced-motion variant.
- Sound: ambient layer with a toggle. **Blocked on licensed audio (R3).**

## Phase 6: Optimisation and accessibility
- Quality selector UI, fullscreen.
- Smooth tier changes (no terrain reload).
- KTX2 / WebP textures.
- Skip link and a text alternative for the canvas.
- Lighthouse and FPS measurements recorded in `docs/development/performance.md`.

## Phase 7: Production
- Build and run the Docker stack (needs Docker Desktop).
- HTTPS (Caddy or certbot instructions), `pg_dump` backup service with rotation, media backup.
- Structured logging, health checks, uptime monitoring guide.
- GitHub Actions CI: tests, typecheck, build, E2E.
